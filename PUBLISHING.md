# Публикация на GitHub

В этой папке находится корень репозитория. Соседняя папка `Release` содержит APK, SHA256 и описание релиза. Локальные журналы отладки, история браузера и ключи подписи в комплект не включены.

1. Создайте пустой репозиторий `Rbrowser` в своём аккаунте GitHub. Не добавляйте туда второй README / LICENSE, если хотите отправить эту папку первым коммитом.
2. Из этой папки выполните команды ниже, заменив OWNER и REPOSITORY на свои значения. Войдите в GitHub своим обычным способом; пароль или токен не записывайте в файлы проекта.

```powershell
git init -b main
git add .
git commit -m "Initial Rbrowser source release"
git remote add origin https://github.com/OWNER/REPOSITORY.git
git push -u origin main
```

Исходники также можно добавить через GitHub Desktop. Убедитесь, что скрытые `.github`, `.gitignore` и `.gitattributes` тоже включены. APK и рабочие `bin` / `obj` не добавляйте в историю Git.

3. В разделе Actions проверки запустятся автоматически. Для сборки APK откройте **Checks and Android build → Run workflow**. Облачная сборка создаёт тестовый APK с временным ключом; она не публикует GitHub Release.
4. Для готового APK создайте Release с тегом `v0.8.2`, приложите APK и `SHA256SUMS.txt` из соседней папки `Release`, вставьте текст из `RELEASE_NOTES.md`.

Первый приложенный APK подписан локальным отладочным ключом и подходит для тестирования. Перед постоянными публичными выпусками используйте собственный стабильный ключ; подробности — [docs/BUILDING.md](docs/BUILDING.md). Файлы ключа в комплект не включены.

Лицензия собственного кода — MIT. Для включённых фильтров и компонентов сохранены отдельные условия в `THIRD_PARTY/NOTICE.md`; не удаляйте их при публикации.

Комплект подготовлен локально. Репозиторий и релиз на GitHub этим комплектом автоматически не создаются.
